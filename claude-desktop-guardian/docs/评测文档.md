# Claude Desktop Guardian Windows 评测文档

## 1. 评测目标

验证 Claude Desktop 在 Windows 上运行时，出站路径持续经过用户指定的 VPN/TUN，VPN、出口 IP、DNS、WebRTC、时区或进程网络状态异常时能够进入阻断状态，并向用户展示可以人工复核的具体检测数据和切断原因。

评测对象是 `claude-desktop-guardian` 独立项目。现有 Windows 账号切换器和 Orca Docker 隔离功能作为检查逻辑参考，评测过程不修改现有安装态、Claude 登录数据、Docker、代理客户端和系统网络设置。

## 2. 保护边界

- 保护当前登录用户启动的 Claude Desktop 主进程和子进程。
- 保护集合按照 Claude 安装路径、进程父子关系和当前用户 SID 建立。
- 出站路径使用系统 VPN/TUN。
- 网络内容保持端到端加密，程序检查连接元数据、TLS 建连和探针结果。
- 阻断只操作带有 `ClaudeDesktopGuardian` 标识和当前用户 SID 的防火墙规则。
- 阻断级异常出现后立即阻断。恢复必须由完整检查确认，用户也可以在面板中手动执行解除。

## 3. 检查矩阵

| 检查项 | 频率 | 通过条件 | 失败动作 |
|---|---:|---|---|
| Claude 进程树 | 5 秒 | 能识别 Claude 主进程及当前用户子进程 | 记录异常并结束保护集合 |
| 代理客户端 | 5 秒 | 配置的客户端进程或服务在线 | 启用阻断并结束 Claude |
| VPN/TUN 网卡 | 5 秒 | 目标虚拟网卡处于 Up 状态并有 IPv4 地址 | 启用阻断并结束 Claude |
| 默认路由 | 5 秒 | 默认网关来自目标 VPN/TUN 网卡 | 启用阻断并结束 Claude |
| 出口 IP | 30 分钟或手动 | 能取得出口且符合目标配置 | 启用阻断并结束 Claude |
| IP 稳定性 | 30 分钟 | 与上次记录一致或处于允许变化策略 | 警告或阻断 |
| DNS | 30 分钟或手动 | Claude 域名解析成功且解析结果符合 VPN 客户端策略 | 启用阻断并结束 Claude |
| IPv6 出口 | 30 分钟或手动 | 检测到公网 IPv6 时，能够通过强制 IPv6 HTTPS 探针取得出口，且国家与目标 IPv4 出口一致 | 无法取得 IPv6 出口或国家不一致时启用阻断并结束 Claude |
| 时区一致性 | 启动和 30 分钟完整检查 | 出口 IP 对应的 IANA 时区可以解析并映射为 Windows 时区，运行中的系统时区与目标一致 | 启动时记录原时区并临时切换，无法解析或切换时在面板显示具体原因 |
| Claude HTTPS | 30 分钟或手动 | 允许域名可以建立 TLS 连接 | 记录故障并按配置阻断 |
| 原生 STUN UDP | 30 分钟或手动 | 有效 STUN 映射地址与 VPN 出口一致 | 启用阻断并结束 Claude |
| 浏览器 WebRTC ICE | 启动、30 分钟或手动 | WebView2 完成 ICE 收集，未出现非预期公网候选 | 确认非 VPN 公网候选时启用阻断，Unknown 仅显示原因 |
| 活动连接 | 5 秒 | 受保护进程连接符合 TCP 443 和允许目标策略 | 启用阻断并结束 Claude |
| 防火墙规则 | 5 秒 | 管理规则存在且处于预期状态 | 进入错误状态并提示修复 |
| 管理员助手 | 5 秒 | 受限命名管道可用且返回有效状态 | 启用已有规则并结束 Claude |
| 监控循环 | 5 秒 | 检查任务按时完成 | 记录超时并保持当前安全状态 |

## 4. 运行策略

- 轻量检查间隔为 5 秒。
- 完整检查间隔为 30 分钟。
- 用户可以随时手动启动完整检查。
- 完整检查开始前先确认 VPN/TUN 路径在线，路径失效时不发起可能走直连的外部探测。
- IPv4 和 IPv6 出口使用独立连接族探针，面板分别显示两条出口。IPv6 只有在在线网卡存在公网 IPv6 地址并且存在 IPv6 默认路由时才进入泄漏检查。链路本地、回环、ULA 地址或没有默认路由的地址不会触发公网 IPv6 检查。
- 出口时区优先通过 `ipapi.co` 解析，失败后通过 `ipinfo.io` 兜底，并将 IANA 时区映射为 Windows 时区 ID。
- Guardian 启动时先恢复上一次未完成的时区临时切换，再执行完整检查。出口时区可用且与当前系统时区不一致时，管理员助手通过 `tzutil` 临时切换系统时区。
- 从托盘选择“退出”时恢复启动前的 Windows 时区。正常关闭失败会保留状态并显示恢复原因，下次启动继续尝试恢复。
- 所有检查结果都带有状态、详情、时间和证据字段。
- 面板显示原始检测数据，持久化日志只保留脱敏摘要。
- WebRTC 同时运行原生 STUN 和 WebView2 浏览器 ICE 检查。面板分别显示 STUN 服务器、地址族、响应状态、浏览器 ICE 完成状态、候选地址类别和失败原因。
- 浏览器 ICE 的 `icecandidateerror` 会记录目标 STUN 地址、错误码和错误文本，并在面板和 WebRTC 检查详情中显示。
- 浏览器 ICE 只发现 mDNS、局域网或回环候选时，仍需原生 STUN 完成验证。任一层无法完成验证时显示未验证，WebRTC 的 Unknown 不会被当作已确认泄露。
- WebView2 Runtime 缺失、初始化失败、页面加载失败、脚本执行失败和 ICE 收集超时都属于未验证。
- VPN/TUN、默认路由、出口 IP、DNS、IPv6、Claude HTTPS 等阻断级检查出现失败或无法验证时，立即执行防火墙阻断并终止 Claude 进程。WebRTC 只有原生 STUN 或浏览器 ICE 明确返回非 VPN 出口的公网地址时才执行阻断。STUN 超时、ICE 超时、WebRTC 禁用、WebView2 失败及其他 WebRTC Unknown 状态只显示未验证，不自动断网。
- 当前 VPN 出口 IP 未取得时，即使 STUN 或 ICE 返回公网地址，也只能显示未验证。只有存在可比较的 VPN 出口基线且地址明确不一致时，才算确认泄露。
- 面板底部的“忽略 WebRTC 阻断”开关会持久化到用户状态。开启后仍执行 WebRTC 检测并显示原始证据，但确认泄露或未验证都不会因为 WebRTC 触发断网。关闭开关后恢复正常阻断逻辑。
- 检测页面固定内置在发布包中，只向配置的 STUN 服务器发起 WebRTC 探测，不加载远程网页资源。

## 5. 切断和恢复验收

### VPN 异常

1. 启动 Claude Desktop。
2. 确认面板显示健康。
3. 停止 VPN 客户端或禁用 VPN/TUN 网卡。
4. 等待一个轻量检查周期。
5. 验证面板进入“已阻断”。
6. 验证面板显示“VPN/TUN 网卡离线”或对应的实际原因。
7. 验证 Claude 主进程和子进程已结束。
8. 验证本程序管理的阻断规则已启用。

### 出口 IP 异常

1. 在隔离测试环境更换 VPN 节点。
2. 手动执行完整检查。
3. 验证出口 IP 变化被显示。
4. 验证不符合目标策略时进入阻断。
5. 验证面板同时显示当前出口、上次出口和比较结果。

### WebRTC 异常

1. 执行完整检查。
2. 验证面板同时显示原生 STUN 结果和浏览器 ICE 结果。
3. 验证每个 STUN 服务的响应状态、返回地址和匹配状态都显示在面板。
4. 验证浏览器 ICE 的完成状态、候选地址、地址族和候选类别都显示在面板。
5. 返回非 VPN 出口地址的原生 STUN 或浏览器公网候选时验证进入阻断。
6. 只有 mDNS 或局域网候选时，验证原生 STUN 未完成仍保持未验证，不把 Unknown 当作泄露阻断。
7. 全部 STUN 无响应时，验证浏览器候选结果不会把 WebRTC 状态伪装成通过。
8. 浏览器 ICE 报告错误时，验证面板显示 STUN 地址、错误码和错误文本，并保持未验证，不自动断网。
9. WebView2 缺失或初始化失败时，验证面板显示具体原因并保持未验证，不自动断网。

### 系统代理与 TUN 组合

1. 保持 TUN 开启，分别测试系统代理开启和关闭。
2. 验证 HTTP 出口、原生 STUN 和浏览器 ICE 的实际结果分别显示。
3. 验证系统代理关闭时，TUN 仍能完成 Claude HTTPS 和浏览器 ICE 检查。
4. 验证系统代理与 TUN 路径结果不一致时，面板保留两类证据并按未验证或失败处理。

### IPv6 出口

1. 保持 VPN/TUN 开启并执行完整检查。
2. 验证面板分别显示 IPv4 出口和 IPv6 出口。
3. 有公网 IPv6 但 IPv6 探针无法建立连接时，验证状态为未验证并显示具体原因。
4. IPv6 出口国家与目标 IPv4 出口不一致时，验证进入阻断。
5. 只有局域网、链路本地或 ULA IPv6 地址时，验证不会误报公网 IPv6 泄漏。

### 时区检测与恢复

1. 启动管理员助手和 Guardian，确认面板显示出口 IANA 时区、目标 Windows 时区和当前系统时区。
2. 选择一个与出口时区不同的系统时区后重启 Guardian。
3. 验证启动阶段先处理上一次残留恢复状态，再执行完整检查。
4. 验证系统时区被临时切换为出口对应的 Windows 时区。
5. 验证面板显示原时区和退出后的恢复目标。
6. 从托盘选择“退出”，确认系统时区恢复为启动前的值。
7. 在管理员助手不可用或时区接口失败时，验证面板显示具体原因且不伪造成功状态。
8. 模拟程序在切换后异常终止，下一次启动验证能够根据状态文件恢复原时区。

### 人工恢复

1. 修复 VPN/TUN 和代理客户端。
2. 点击“重新检查并解除阻断”。
3. 检查不通过时验证恢复按钮继续保持阻断。
4. 检查全部通过后确认解除。
5. 验证防火墙规则只解除本程序管理的规则。
6. 验证程序不会自动启动 Claude。

## 6. 测试层级

- 核心单元测试使用合成网络、进程和时间提供器。
- 管理员助手测试使用模拟防火墙执行器，不修改真实规则。
- WPF 测试验证状态颜色、按钮门禁和原因显示。
- PowerShell 静态检查验证新脚本保持 UTF-8 with BOM。
- Windows 虚拟机验收验证真实 VPN、进程树、管理员助手和防火墙规则。

## 7. 已知边界

- Windows 防火墙规则和进程急停之间存在操作系统调度窗口，记录为防护边界。
- 原生 STUN 结果表示当前系统 UDP 探针的结果，浏览器 ICE 结果表示 WebView2 中实际生成的浏览器候选。
- STUN 无响应可能由节点、UDP 策略或服务器可达性造成。无响应不会被当作没有泄漏。
- 浏览器 ICE 完成且没有公网候选只能说明本次浏览器候选没有展示公网地址。原生 STUN 未验证时，整体 WebRTC 检查保持 Unknown，等待下一次完整检查或用户手动处理。
- 浏览器候选与 VPN 出口一致时属于允许的代理出口候选。出现其他公网地址时按泄漏处理。
- 本机开发构建和隔离测试不能代替真实 WebView2 Runtime、VPN、节点 UDP 转发和 Windows 网络路径验收。
- Electron 子进程路径可能随 Claude 更新变化，进程树会在运行期间动态补充。
- AppX 和传统 EXE 的启动入口不同，必须分别完成安装路径验收。
- IPv6 出口探针依赖当前 VPN 和系统具备可用的公网 IPv6 路由，无法取得出口时按 Fail-Closed 规则阻断。
- 时区自动切换需要管理员助手具备修改系统时区的权限。IP 地理服务不可达时不会猜测时区，也不会修改系统时区。
- 本机开发构建和隔离测试不能代替真实 Windows VPN、管理员权限和防火墙现场验收。

## 8. 发布前验证记录

以下命令用于发布前的可重复验证，不会启动 Guardian，不会修改系统网络、时区、防火墙或 Claude 登录态。

```powershell
dotnet run --project tests\ClaudeDesktopGuardian.Tests.csproj -c Release
dotnet build src\ClaudeDesktopGuardian.App\ClaudeDesktopGuardian.App.csproj -c Release
dotnet build src\ClaudeDesktopGuardian.Helper\ClaudeDesktopGuardian.Helper.csproj -c Release
node --check src\ClaudeDesktopGuardian.App\web\webrtc\leak-check.js
```

发布目录必须同时包含以下文件：

- `ClaudeDesktopGuardian.App.exe`
- `Microsoft.Web.WebView2.Wpf.dll`
- `Microsoft.Web.WebView2.Core.dll`
- `WebView2Loader.dll`
- `web\webrtc\index.html`
- `web\webrtc\leak-check.js`

当前发布验证已确认核心测试、App 构建、管理员助手构建和 WebRTC JavaScript 语法检查通过。真实 WebView2 Runtime、VPN/TUN、UDP STUN 和防火墙动作仍需在目标 Windows 机器按本文件第 5 节执行现场验收。
