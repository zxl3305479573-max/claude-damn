# claude-damn Windows 评测文档

## 1. 评测对象与范围

本评测覆盖仓库根目录项目（.NET 8 / WPF 桌面端 `ClaudeDesktopGuardian.App`、提权命名管道助手 `ClaudeDesktopGuardian.Helper`、控制台入口 `ClaudeDesktopGuardian.Cli` 与共享核心 `ClaudeDesktopGuardian.Core`），融合 Windows 端网络守护、24 项环境体检、Clash 规则审计修复、A–D 多账号事务隔离、`.csnap` 加密快照及维护诊断工具。

产品已包含 GitHub Release OTA。本文本轮只验证仓库代码与发布构建，不执行 OTA、部署、真实网络故障注入或修改维护者安装态。Docker 容器隔离不在本产品范围内。

结果统一区分：成功采集且符合策略（Ok）、确认违反策略（Fail/Warn）、采集失败或证据不足（Unknown）、用户关闭或功能未启用（Skip）。TCP-only 开启时 Fail 与 Unknown 均阻止启动，不能被可选项降级。完整检查及后续轻量检查固定输出 24 项。保留 5 秒轻量、30 分钟完整检查周期。

证据解释边界：HTTP 响应可达不等于访问获准，更不等于账号可登录或消息可发送；UDP 绑定端点不证明已经发送数据；防火墙规则读回不等于抓包验收；Guardian 的 WebRTC 探针不直接代表 Claude 内部 WebRTC；信誉源未配置、缺字段或过期均不代表 IP 干净。

TCP-only 仅使用 `ClaudeDesktopGuardian.<SID>.TcpOnly` 专用组，识别当前用户 Claude EXE/MSIX 身份，不接收任意程序目标、不包括代理内核。启用、启动恢复与显式修复重新读回；运行中规则缺失/过期触发既有 Fail-Closed；正常退出和卸载仅清理本组规则，保留开关设置以便下次重建，不碰手工规则。

自动化验证使用假执行器、合成原生结果和隔离本地服务，不改真实网络、防火墙、代理、系统设置、账号或安装目录。目标门禁为现有测试、App/Helper/CLI 构建、JavaScript 语法、PowerShell BOM/AST、完整 publish 构建与 `git diff --check`。

真机待测：TCP-only 抓包、既有连接退出、代理核心不受影响、手工规则保留、重启恢复与卸载清理、WFP 双栈具体目的地、系统策略覆盖、真实 TUN 重建与相同网卡节点切换。以上未在本轮执行，状态均为 **待测**；不能以模拟测试或规则读回冒充真机通过。

## 2. 保护边界与安全不变量

- **受保护对象**：当前登录用户 SID 下、来自已识别安装路径（`%LOCALAPPDATA%\AnthropicClaude`、`%LOCALAPPDATA%\Programs\Claude`、`WindowsApps\Claude_`）的 Claude Desktop 主进程及其子进程树。
- **双层出站控制**：
  - 防火墙急停层：仅操作当前用户组 `ClaudeDesktopGuardian.<SID>` 下的出站阻断规则；重复下发前幂等清理旧规则，不产生重复叠加。
  - WFP 内核层（可选严格模式）：在 IPv4/IPv6 `ALE_AUTH_CONNECT` 阶段限制 Claude 可执行文件与 MSIX 包 SID 仅允许经指定 TUN 接口 LUID 出站（可配置是否放行本机回环）。启用时终止当前用户既有 Claude Desktop 进程并复核退出，防止旧 TCP 连接绕过内核过滤。
- **Fail-Closed 阻断锁定**：阻断级异常且 Claude 运行时立即下发防火墙阻断并终止进程树，状态持久化到 `state.json`。Claude 退出或轻量周期检查不自动解除阻断；阻断期间 Claude 再次启动时重新强制终止。仅用户触发“检查并解除阻断”且有效阻断失败数为 0 时解除。
- **严格路径门禁**：代理客户端或 VPN/TUN 网卡离线时立即跳过所有外网探针，防止在直连路径上暴露真实 IP。
- **单实例、管道与操作互斥**：WPF 主程序通过 `Local\ClaudeDesktopGuardian.SingleInstance` 防双开；多账号切换与快照通过 `Local\ClaudeDesktopGuardian.AccountOp` 串行；`pipe.token` 原子独占创建并仅限当前用户与系统管理员读写；Helper 命名管道支持并发只读 `status` 查询，写操作经内部锁串行并具备外部子进程超时保护。
- **热路径零子进程风暴**：5 秒轻量巡检稳态下不启动 `powershell.exe` 或 `tzutil.exe`（MSIX 包信息优先直读注册表并带 60 秒 TTL 缓存，写操作强制刷新；系统时区直读 `TimeZoneInfo.Local`）；进程树扫描先按 `PROCESSENTRY32` 内存树过滤，再仅对 Claude 候选 PID 调用单次 `OpenProcess` 读取路径与令牌。
- **多账号与 CLI 退出红线**：账号数据独立存于 `%LOCALAPPDATA%\ClaudeDesktopGuardian\accounts`。切换前必须完整安检通过、未处于阻断态，并等待当前用户全部 Claude Desktop 与 Claude Code CLI 进程退出（最多 10 秒）；超时仍存活则中止切换，桌面数据与当前槽位指针保持不变。
- **脱敏边界**：面板可显示原始检测证据及选中检查项的结构化 `Evidence`；持久化日志 `logs\guardian.log`（512 KiB 自动轮转）与诊断 `.zip` 禁止包含出口/代理 IP、API Key、凭据、账号内容、Clash 配置或原始检查详情（含 `{ip}` 模板的信誉源仅记录脱敏主机名 `url_host`）。独立代理诊断（`diagnose-proxy`）不写客户端日志、不创建账号状态、不修改系统设置。

## 4. 核心机制规格

- **巡检周期与超时保护**：默认每 5 秒执行轻量检查（保留完整 24 行，不每 5 秒发 UDP STUN），每 30 分钟完整检查；出口基线最多 60 秒刷新。同网卡换出口、TUN 身份/地址、DNS、相关路由与系统代理变化使依赖缓存失效。超时保留旧观测时间、显示陈旧/Unknown 并排队完整复检，确认 Fail 不降级，不重置上次成功完整检查时间。单次巡检强制绑定超时取消（轻量 20 秒、完整 45 秒），管道读写绑定 12 秒超时，Helper 外部进程默认绑定 15 秒超时。
- **真单项复检与 Evidence 排查**：行内“复检”与 CLI `check-item <id>` 经 `ISingleCheckProbe` 重测目标与最小依赖，并重新评估相关检查，不保留已失效的硬检查旧绿色；上下文变化或出口基线到期时升级为完整依赖刷新与 ICE 重测。单项复检超时或失败仅将目标项标为陈旧/`Unknown`（保留既有 `Fail`），不连带污染其他检查项。其他单项不触发无关探测。点击面板检查矩阵任意行，右侧实时展开完整详情与结构化 `Evidence`（支持一键复制）。
- **系统代理与 TUN 路径一致性**：检测到系统配置了 HTTP/HTTPS 代理时，并行发起经系统代理与绕过代理直走 TUN 两条 IPv4 出口探测，界面同时展示两类证据；TUN 直连为 `CN` 或国家不一致判 `Fail`，TUN 不可达或同国不同出口 IP 判 `Unknown` 阻断。
- **多源出口与时区同步**：IPv4 出口按 Cloudflare trace → `ipinfo.io` → `ipwho.is` → `api.ip.sb` 兜底；出口时区按 `ipapi.co` → `ipinfo.io` → `ifconfig.co` → `ipwho.is` → 国家默认 IANA 映射并转为 Windows 时区 ID。启动时先恢复上次残留临时时区，托盘退出或 `install.ps1 -Uninstall` 调用 `Helper --cleanup-all` 统一恢复原时区、清防火墙规则并移除 WFP 子层。
- **IP 信誉缓存规则**：TTL 有效期内直接命中本地缓存；缓存过期且本次刷新失败时显式回报过期刷新失败告警，不静默伪装新鲜结果；缓存文件触及 256 KiB 上限时按 `CheckedAt` 淘汰最旧条目。
- **安全启动门禁与助手重连**：点击“安全启动 Claude”前评估 `ProtectionPolicyEvaluator.EvaluateLaunchGate`，处于阻断态、路径离线或存在有效阻断失败（含严格 WFP 未 `active`）时拒绝启动。若助手离线或此前取消过 UAC，可在界面直接点击“启动 / 重连助手”恢复连接。
- **Clash 修复与验证**：`global`/`direct`/`unknown` 仅清理旧 `Merge.yaml` 不改 `Script.js`；`rule` 模式按 `proxy`/`reject` 写入仅匹配 UDP 的 `AND,((NETWORK,UDP),(DST-PORT,...))` 规则并用非提升赋值包裹保留原有 `main`，重启后轮询 `/rules` 前 16 条，失败自动从备份回滚。FlClash 自动探测本机监听口。
- **WebRTC 双层规则**：原生 STUN 与内置 WebView2 本地页并行探测；仅当存在可比较的 VPN 出口基线且出现其他公网地址时判确认泄露（`Fail`）。“忽略 WebRTC 未验证”仅消除 `Unknown` 对主状态的提示，不屏蔽确认泄露。“拒绝”策略仅在 Clash 置顶规则已核验加载且浏览器 ICE 完成无公网候选时把 STUN 全静默判 `Ok`。
- **单目录共享运行时打包与 CLI 契约**：`build.ps1` 将 `App.exe`、`Helper.exe`、`Cli.exe` 发布到同一自包含 `win-x64` 目录共享单份 .NET 8 运行时（总发布体积 < 195 MB）；`install.ps1` 支持 `-InstallDir` 自定义安装路径并在卸载时兼容同目录与旧 `helper\` 布局。CLI `diagnose-proxy` 退出码：`0`=传输到达，`1`=传输失败，`2`=配置错误。
